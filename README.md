# Prompt Coach · 提示词共创

把一个问题、方向、目的或已有提示词，通过关键追问和草稿迭代，完善为可直接交给 Agent 使用的完整提示词；中高风险场景按需附上结构化输出契约、测试样例与失败模式诊断。

## 工作方式

1. 先做范围判断：新提示词共创、旧提示词评审、多步工作流三条路线。
2. 明确最终目的，提取已有背景和约束；每轮默认只问一个关键问题，必要时最多三个。
3. 及时提供草稿，把用户回答和适用方法直接合并进提示词。
4. 中高风险或用户要求时，补充 JSON Schema、五类测试行与版本化试验；评审旧提示词时先给问题清单再给完整修订版。
5. 信息足够或用户要求交付时，给出完整、可复制的最终提示词。

默认交付提示词；用户明确要求后，才试运行或执行其中的任务。未知条件、假设和工具限制会明确标注；没有实测证据时只写“预计”效果。

## 目录

```text
prompt-coach/
├── SKILL.md                     # Skill 定义与交互规则
├── README.md                    # 使用说明
└── references/
    ├── test-cases.md            # 测试样例、失败模式与版本化试验模板
    └── review-checklist.md      # 旧提示词六维评审清单
```

## 使用

支持目录式 Skills 的 Agent：将整个 `prompt-coach` 文件夹放入该平台规定的技能目录，并按平台要求加载或启用。

不支持 Skills 的 Agent：将 `SKILL.md` 中 YAML 元数据之后的正文放入 Agent 的自定义指令区。

一句话开始：

```text
使用 prompt-coach：我想让 AI 帮我做产品竞品分析，请通过交流帮我完善提示词，最后交付完整提示词。
```

评审旧提示词：

```text
使用 prompt-coach 评审这份旧提示词，这是它的失败输出样例，请按评审清单给问题清单和修订版。
```

随时要求直接交付：

```text
按现有信息直接给我最终提示词，不再追问；未知条件和必要假设请写进提示词。
```

最终提示词可复制到新对话中使用；其中标明待提供的材料，需要在执行时补齐。
